# Contributing

## Development setup

You need **Go 1.27.4 or later** (see `go.mod`).

```sh
git clone https://github.com/arush-sal/gt7-telemetry-collector
cd gt7-telemetry-collector
go build ./...
go test ./...
go run ./cmd/gt7-collector --version
```

Protobuf code is generated from `proto/` (see `buf.yaml` and `buf.gen.yaml`) into
`gen/`. The car reference tables in `gt7data` are generated by
`gt7data/internal/gen`.

## Quality gates

Run these before opening a pull request. CI runs the same checks.

```sh
gofmt -l .                      # must print nothing
golangci-lint run               # golangci-lint v2, config in .golangci.yml
go vet ./...
go test -race ./...
govulncheck ./...
```

Exported identifiers need a doc comment that starts with their name (enforced by
the `revive` `exported` rule).

## CI workflows

| Workflow | Trigger | What it does |
| --- | --- | --- |
| `test.yml` | push and PR to `master`, reusable | golangci-lint, `go vet`, `go test -race` with coverage. |
| `security.yml` | push and PR to `master`, weekly, reusable | Trivy filesystem scans, zizmor audit of workflows, govulncheck. |
| `build.yml` | push and PR to `master` | Security checks, then a GoReleaser snapshot build. |
| `release.yml` | tag `v*` | Security and tests, then GoReleaser, then build provenance attestation. |
| `docs.yml` | `docs/**`, `mkdocs.yml` changes | Trivy scan, `mkdocs build --strict`, deploy to GitHub Pages (master only). |

All actions are pinned by full commit SHA.

## Building the docs

```sh
python3 -m venv .venv && . .venv/bin/activate
pip install -r docs/requirements.txt
mkdocs serve          # live preview
mkdocs build --strict # what CI runs; output goes to site/
```

## Releasing

Pushing a tag that matches `v*` runs the release workflow: it runs the security
and test workflows, then GoReleaser builds archives for linux, darwin and
windows (amd64, arm64), writes `checksums.txt` and SBOMs, signs every artifact
with keyless cosign, publishes the GitHub Release, and attests build provenance.

```sh
git tag -s v0.1.0 -m "v0.1.0"
git push origin v0.1.0
```

Tags containing a pre-release suffix are published as pre-releases.
